# Agents Directory

Этот каталог содержит конфигурацию и скрипты для запуска AI-агентов, включая агент на модели Opus 4.5.

## Структура каталога

```
agents/
├── README.md                     # Этот файл
├── run_opus_agent.js            # Скрипт для запуска Opus 4.5 агента
├── tools/                       # Документация инструментов
│   └── runSubagent.md          # Описание инструмента runSubagent
└── Dockerfile                   # Docker конфигурация для запуска агентов
```

## Конфигурация Opus 4.5 Agent

Конфигурационный файл агента находится по адресу: `.github/agents/opus-4.5-agent.json`

### Основные параметры конфигурации:

- **name**: `opus-4.5-agent` - уникальное имя агента
- **model**: `opus-4.5` - идентификатор модели (может отличаться в зависимости от провайдера)
- **mode**: `agent` - режим работы агента
- **initial_message**: начальное сообщение, которое выполняется при запуске агента
- **tools**: список доступных инструментов, включая `runSubagent`

## Быстрый старт

### Предварительные требования

- Node.js версии 14 или выше
- API ключ для доступа к модели Opus 4.5

### Шаг 1: Установка переменных окружения

Установите API ключ в одну из следующих переменных окружения:

```bash
# Вариант 1: Специфичная переменная для Opus
export OPUS_API_KEY="your-api-key-here"

# Вариант 2: Anthropic API ключ
export ANTHROPIC_API_KEY="your-api-key-here"
```

При необходимости можно также настроить endpoint API:

```bash
export OPUS_API_ENDPOINT="https://api.anthropic.com/v1/messages"
```

### Шаг 2: Запуск агента

```bash
# Из корня репозитория
node agents/run_opus_agent.js
```

## Настройка

### Изменение имени субагента

Чтобы изменить имя субагента, отредактируйте файл `.github/agents/opus-4.5-agent.json`:

```json
{
  "initial_message": "Запустите субагента 'time-agent' с помощью инструмента runSubagent и передайте запрос: 'Сколько времени в Лондоне, Великобритания?'."
}
```

Замените `time-agent` на желаемое имя субагента. **Важно:** имя субагента не должно совпадать с именем текущего агента, чтобы избежать рекурсии.

### Изменение модели

Если ваш провайдер использует другой идентификатор модели, измените поле `model` в конфигурации:

```json
{
  "model": "claude-opus-4.5"  // или другой идентификатор
}
```

### Изменение начального запроса

Вы можете изменить запрос, передаваемый субагенту:

```json
{
  "initial_message": "Запустите субагента 'opus-4.5-agent' с помощью инструмента runSubagent и передайте запрос: 'Ваш новый запрос здесь'."
}
```

## Запуск с Docker

### Сборка образа

```bash
docker build -t opus-agent -f agents/Dockerfile .
```

### Запуск контейнера

```bash
docker run -e OPUS_API_KEY="your-api-key-here" opus-agent
```

Или с файлом переменных окружения:

```bash
# Создайте файл .env
echo "OPUS_API_KEY=your-api-key-here" > .env

# Запустите контейнер
docker run --env-file .env opus-agent
```

## Инструменты

### runSubagent

Инструмент `runSubagent` позволяет запускать субагентов и передавать им запросы для обработки.

**Сигнатура:**
```
runSubagent(name: string, input: string)
```

**Параметры:**
- `name` - имя субагента для запуска
- `input` - входной запрос для субагента

Подробную документацию см. в [tools/runSubagent.md](tools/runSubagent.md)

## Устранение неполадок

### Ошибка: API ключ не установлен

```
❌ Ошибка: не установлен API ключ!
Пожалуйста, установите переменную окружения OPUS_API_KEY или ANTHROPIC_API_KEY
```

**Решение:** Установите одну из переменных окружения с вашим API ключом.

### Ошибка: Файл конфигурации не найден

```
❌ Файл конфигурации не найден: .github/agents/opus-4.5-agent.json
```

**Решение:** Убедитесь, что вы запускаете скрипт из корневого каталога репозитория.

### Ошибка API

```
❌ Ошибка API: { ... }
```

**Решение:** 
- Проверьте корректность API ключа
- Убедитесь, что API endpoint настроен правильно
- Проверьте, что модель `opus-4.5` доступна для вашего аккаунта
- Проверьте формат запроса в соответствии с документацией провайдера

## Безопасность

⚠️ **Важно:**
- Никогда не коммитьте API ключи в репозиторий
- Используйте переменные окружения для хранения секретов
- Добавьте `.env` файлы в `.gitignore`
- Используйте безопасные методы хранения секретов в production среде
